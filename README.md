# WoW Fishing Automation

Программа автоматизирует цикл рыбалки в World of Warcraft Anniversary Edition /
The Burning Crusade Classic: делает заброс, ищет поплавок на изображении,
видит его резкое движение при поклёвке и забирает улов.

> **Важно:** автоматизация может нарушать правила World of Warcraft. Вы
> используете программу на свой риск. Сначала обязательно настройте и проверьте
> её в безопасном режиме `--dry-run`, в котором мышь и клавиатура не нажимаются.

## Что понадобится

- компьютер с **Windows 10 или Windows 11**;
- установленный **64-битный Python 3.12**;
- установленный World of Warcraft;
- несколько собственных PNG-изображений поплавка;
- примерно 15–30 минут для первоначальной настройки.

Проект использует OpenCV, NumPy, MSS и pynput. По умолчанию звук не нужен:
поклёвка определяется визуально в маленькой области вокруг поплавка.
PyAudioWPatch установлен как необязательный запасной WASAPI audio-режим.

## Быстрый порядок действий

Если вы впервые пользуетесь Python, выполняйте разделы строго по порядку:

1. Установите Python 3.12.
2. Откройте PowerShell в папке проекта.
3. Создайте и активируйте виртуальное окружение.
4. Установите зависимости.
5. Запустите мастер `python main.py --setup` — редактировать Python не нужно.
6. Один раз выполните `python main.py --calibrate`: мастер сделает пять тестовых
   забросов и попросит подтвердить найденный поплавок.
6. Проверьте полный цикл в `--dry-run`.
7. Только после успешной проверки запустите обычный режим.

## Шаг 1. Установка Python 3.12

1. Откройте официальный сайт [python.org](https://www.python.org/downloads/).
2. Найдите выпуск Python **3.12.x** и скачайте **Windows installer (64-bit)**.
3. Запустите установщик.
4. На первом экране обязательно установите флажок **Add python.exe to PATH**.
5. Нажмите **Install Now** и дождитесь завершения.
6. Откройте меню «Пуск», введите `PowerShell` и запустите Windows PowerShell.
7. Проверьте установку:

```powershell
py -3.12 --version
```

Ожидается строка наподобие `Python 3.12.10`. Если команда `py` не найдена,
закройте и заново откройте PowerShell. Если это не помогло, повторите установку
Python и проверьте флажок добавления в PATH.

> Не используйте Python 2 или Python 3.13/3.14 для первой установки этого
> проекта. Поддерживаемая и рекомендуемая версия — Python 3.12.

## Шаг 2. Подготовка папки проекта

Распакуйте или скопируйте проект в простой путь, например:

```text
C:\wow-fishing
```

Не помещайте его в `C:\Program Files`, потому что Windows может ограничить
запись диагностических файлов.

Чтобы открыть PowerShell непосредственно в папке:

1. Откройте папку проекта в Проводнике.
2. Щёлкните адресную строку.
3. Введите `powershell` и нажмите Enter.
4. Убедитесь, что PowerShell видит файлы:

```powershell
Get-ChildItem
```

В списке должны быть `main.py`, `config.py`, `requirements.txt`, папки
`fishing_bot`, `templates` и `tools`.

## Шаг 3. Виртуальное окружение

Виртуальное окружение хранит библиотеки проекта отдельно от других программ.
Его нужно создать только один раз:

```powershell
py -3.12 -m venv .venv
```

Затем активируйте его:

```powershell
.\.venv\Scripts\Activate.ps1
```

Если PowerShell сообщает, что выполнение сценариев запрещено, разрешите их
только для своего пользователя, после чего повторите активацию:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
.\.venv\Scripts\Activate.ps1
```

На вопрос PowerShell ответьте `Y`. После активации слева от приглашения появится
`(.venv)`. При каждом новом открытии PowerShell снова выполняйте только команду
активации; повторно создавать `.venv` не нужно.

Альтернатива для обычной командной строки `cmd.exe`:

```bat
.venv\Scripts\activate.bat
```

## Шаг 4. Установка зависимостей

С активным `(.venv)` выполните:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Установка может занять несколько минут. Затем проверьте основные импорты:

```powershell
python -c "import cv2, numpy, mss, pynput, pyaudiowpatch; print('Все библиотеки установлены')"
```

Если появилась строка `Все библиотеки установлены`, Python готов. Если выводится
`ModuleNotFoundError`, убедитесь, что слева есть `(.venv)`, и повторите установку
requirements. Не устанавливайте старые `pyaudio`, `autopy`, `pyscreenshot` или
`audioop` — проект их не использует.

## Шаг 5. Автоматическая первоначальная настройка

Запустите:

```powershell
python main.py --setup
```

Мастер спросит клавишу заброса, наживку и режим detector, после чего атомарно
сохранит локальный `user_config.json`. Открывать и редактировать `config.py` не
нужно. По умолчанию выбирайте `auto`.

Перед запуском мастера:

1. Запустите игру в оконном или полноэкранном оконном режиме.
2. Выберите разрешение и масштаб интерфейса, с которыми будете играть постоянно.
3. Назначьте Fishing и наживку на удобные клавиши — их спросит мастер.
4. Убедитесь, что название активного окна содержит `World of Warcraft`.
5. Для необязательного audio-режима убедитесь, что звук игры слышен.

Если WoW и PowerShell запущены с разными правами, Windows может блокировать
управление вводом. Обычно обе программы следует запускать без прав
администратора. Если WoW запущен от администратора, PowerShell также потребуется
запустить от администратора.

## Шаг 6. Область поиска: всё окно по умолчанию

При первом запуске ничего выделять и вычислять не нужно. По умолчанию
`search_mode = "window"`: перед каждой попыткой программа заново определяет
текущую клиентскую область WoW и ищет поплавок по всему окну игры. Рамка окна,
панель задач, другие программы и дополнительные мониторы в снимок не попадают.

Это самый простой режим, и его рекомендуется попробовать первым. Он также
автоматически учитывает перенос и изменение размера окна WoW между попытками.
На 1440p/4K или при большом числе шаблонов поиск может потреблять больше CPU, а
элементы игрового интерфейса иногда дают ложные совпадения. Только в этих случаях
используйте необязательный визуальный выбор компактной области воды.

### Необязательный выбор компактной области

Программа сделает снимок окна WoW, а вы обведёте мышью часть воды:

1. Запустите WoW в оконном или полноэкранном оконном режиме и подойдите к воде.
2. В PowerShell с активным `(.venv)` запустите:

   ```powershell
   python main.py --select-region
   ```

   Равнозначная отдельная команда:

   ```powershell
   python tools/select_search_region.py
   ```

3. Начнётся пятисекундный обратный отсчёт. За это время переключитесь в WoW и
   оставьте окно игры активным.
4. Программа определит клиентскую область WoW и откроет её неподвижный снимок.
5. Зажмите левую кнопку мыши и обведите участок воды, куда обычно падает
   поплавок. Не включайте панели интерфейса и весь экран: компактная область
   работает быстрее и даёт меньше ложных совпадений.
6. Нажмите **Enter** или **Space**, чтобы подтвердить. Нажмите **C** или **Escape**,
   чтобы отменить выбор — существующие настройки при этом не изменятся.

Готовые координаты автоматически сохраняются в `user_config.json` вместе с
`"search_mode": "custom"`. Редактировать `config.py` не требуется. Для проверки также создаётся
`debug\selected_search_region.png`; откройте его и убедитесь, что там находится
нужный участок воды. После успешного выбора программа напечатает следующую
рекомендуемую команду.

`user_config.json` является локальным пользовательским файлом и не добавляется в
Git. Если область выбрана неправильно, просто снова запустите
`python main.py --select-region` — новый выбор заменит предыдущий.

Программа включает Windows DPI awareness и преобразует положение выделения из
координат окна WoW в физические координаты экрана. Это учитывает рамку окна,
масштабирование Windows 100/125/150%, перенос WoW на дополнительный монитор и
отрицательные координаты мониторов слева или выше основного. После изменения
разрешения игры, UI scale, Windows scaling или расположения окна выберите область
заново.

Чтобы разово проигнорировать пользовательскую область и проверить всё окно WoW,
запустите `python main.py --full-window`. Чтобы постоянно вернуться к режиму
всего окна, удалите `user_config.json` и перезапустите программу. Ручные значения
`Region` остаются запасными настройками custom-режима.

## Шаг 6.5. Автокалибровка под ваш поплавок

После выбора клавиш рекомендуется один раз запустить:

```powershell
python main.py --calibrate
```

Мастер выполнит пять тестовых забросов. В каждой попытке он сравнивает кадр до
и после заброса, находит появившийся цветной объект и ставит на него курсор.
Ответьте `Y`, только если курсор действительно находится на поплавке; при
ошибке ответьте `N`. Отклонённый кандидат не попадает в профиль. Желательно
сделать подтверждённые попытки при немного разном положении камеры и освещении.

Из подтверждённых кадров программа сама вычисляет оттенки, минимальную
насыщенность/яркость и допустимую площадь цветной части. Результат сохраняется
в локальный `calibration_profile.json`; вручную переносить числа в `config.py`
не нужно. При следующих запусках автоматический поиск загружает этот профиль,
но по-прежнему требует появления объекта после заброса и его устойчивости в
нескольких кадрах.

Повторите калибровку после смены UI scale, графики, модели поплавка или при
регулярных ложных выборах. Если новая калибровка неудачна, удалите
`calibration_profile.json`: бот вернётся к общим красно-синим диапазонам. Файл
содержит только числовую статистику, не снимки экрана, и исключён из Git.

## Шаг 7. Необязательные шаблоны поплавка

В режиме `auto` PNG не обязательны. Бот сравнивает кадр до заброса с кадрами
после него, находит новую устойчивую красную или синюю компоненту и автоматически
создаёт временный шаблон. Файлы в `templates/` используются как fallback, если
автоматический поиск не уверен.

1. Запустите WoW и вручную забросьте удочку.
2. Пока поплавок виден, переключитесь в PowerShell и выполните:

   ```powershell
   python tools/capture_region.py
   ```

   В режиме всего окна начнётся пятисекундный отсчёт: вернитесь в WoW, чтобы
   программа смогла определить его клиентскую область.

3. Откройте `debug\latest_capture.png` в Paint, Paint.NET или другом редакторе.
4. Выделите небольшой прямоугольник непосредственно вокруг поплавка. Не
   оставляйте большое количество воды или игрового интерфейса.
5. Обрежьте изображение и сохраните его как PNG:

   ```text
   templates\bobber_01.png
   ```

6. Повторите процесс и создайте `bobber_02.png`, `bobber_03.png` для разных:
   освещений, ракурсов, типов воды, размеров и состояний поплавка.

Шаблон должен быть меньше области поиска и создаваться при том же разрешении,
UI scale и Windows scaling. Шаблоны загружаются один раз при запуске.

## Шаг 8. Необязательная проверка template fallback

Запустите WoW, вручную забросьте удочку и выполните:

```powershell
python tools/test_bobber_detection.py
```

В стандартном режиме будет пять секунд, чтобы переключиться обратно в WoW и
дождаться поплавка. Тест захватит только клиентскую область игры.

В PowerShell появятся confidence для каждого PNG и строка `BEST`. Откроется окно
с рамкой вокруг лучшего совпадения; нажмите любую клавишу, чтобы закрыть его.

Хороший результат должен иметь `found=True`, рамку точно вокруг поплавка и
confidence выше `bobber_confidence` из `config.py` (по умолчанию `0.75`). Если:

- рамка неверная — сделайте более точные шаблоны и уменьшите область поиска;
- правильный поплавок имеет 0.70–0.74 — осторожно снизьте confidence;
- ложные объекты проходят порог — повысьте confidence;
- окно теста не открывается — убедитесь, что запускаете команду в обычной
  Windows-сессии, а не через удалённый терминал без рабочего стола.

## Шаг 9. Автоматическое сопровождение и определение поклёвки

По умолчанию используется:

```python
bite_detection_mode: str = "auto"
```

Перед забросом программа сохраняет серию фоновых кадров и строит медианный фон с
картой обычного движения воды. После заброса она подавляет уже существовавшие
волны и ищет новый устойчивый составной объект: красно-синее перо, светлый
пробковый корпус и яркую металлическую часть. PNG для этого не нужен. Из
найденного объекта автоматически создаётся временный цветной шаблон,
после чего tracker сопровождает ближайшую компоненту в небольшом ROI. Это
заимствует удачную идею FishingFun, но использует быстрые OpenCV connected
components вместо перебора отдельных пикселей.

Кандидаты оцениваются не только по площади. Scorer учитывает цвет пера,
бежевый корпус, компактную яркую деталь, контуры, форму и возможный вертикальный
сегмент лески. Центральность имеет небольшой вес, поэтому заброс возле края окна
не отбрасывается. Если два лучших объекта имеют почти одинаковую оценку, бот
считает результат неоднозначным и безопасно продолжает наблюдение вместо клика
по воде.

Если в `templates/` добавлены несколько вариантов поплавка, они теперь служат
дополнительным подтверждением кандидата в нескольких масштабах, а не единственным
источником координат. Проверка выполняется только в маленьких ROI кандидатов,
поэтому набор из разных ракурсов и освещений не требует полного многомасштабного
поиска по каждому пикселю всего окна. В debug-режиме оценки отдельных признаков
записываются в `debug/latest_auto_candidates.json`.

Подвижность поплавка учитывается: tracker обновляет X/Y на каждом кадре и
перемещает ROI вслед за ним. Невозможные скачки координат отклоняются. Первые
кадры автоматически измеряют обычное покачивание, после чего поклёвкой считается
резкое падение Y относительно медианного положения. Поэтому вручную подбирать
motion, confidence и velocity для обычного auto-режима не требуется.

Вся попытка имеет единый `fishing_attempt_timeout`, который начинается в момент
заброса. Задержка, поиск, сопровождение и ожидание поклёвки расходуют одни и те
же 20 секунд. Бот не пытается кликнуть, если до естественного исчезновения
поплавка осталось меньше `loot_safety_margin`.

Поплавок ищется заново по всей клиентской области после каждого заброса, поэтому
он может появляться в любом месте. После обнаружения auto tracker обновляет
координаты цветного пера и перемещает локальный ROI. При потере компоненты
попытка завершается безопасно; template fallback может выполнить ограниченное
повторное обнаружение. Координаты предыдущего заброса не используются.

Для отдельной проверки вручную забросьте удочку и выполните:

```powershell
python tools/test_visual_bite_detection.py
```

За пять секунд переключитесь обратно в WoW. Утилита найдёт поплавок, ничего не
нажимая, и будет ждать его движения. Результат `BITE` означает успешное
срабатывание; `TIMEOUT` — что порог не был достигнут. Последний диагностический
ROI сохраняется в `debug\latest_auto_bite.png`, а бинарная цветовая маска — в
`debug\latest_colour_mask.png`.

Auto-режим использует безопасные границы в `config.py`:

- `auto_find_*` — фильтры нового объекта и число подтверждающих кадров;
- `auto_background_*` — число фоновых кадров и подавление обычного движения воды;
- `auto_min_candidate_score` — минимальная комплексная оценка внешнего вида;
- `auto_min_score_gap` — необходимое преимущество над вторым кандидатом;
- `auto_hue_tolerance` — допустимое изменение оттенка пера;
- `auto_tracking_padding` — локальная область сопровождения;
- `auto_baseline_frames` / `auto_baseline_window` — автоматический baseline Y;
- `auto_min_bite_drop` — минимальное падение даже при спокойной воде;
- `auto_jitter_multiplier` — порог относительно обычного покачивания;
- `auto_max_frame_shift` — защита от прыжка на другой объект;
- `auto_lost_frames` — допустимая кратковременная потеря цветной компоненты.

Следующие `visual_*` параметры относятся только к расширенному template/motion
fallback-режиму `--bite-mode visual`:

- `visual_bite_roi_padding` — запас пикселей вокруг шаблона;
- `visual_baseline_frames` — число кадров калибровки спокойной воды;
- `visual_pixel_difference` — минимальное изменение отдельного пикселя;
- `visual_motion_threshold` — минимальная доля изменившихся пикселей;
- `visual_motion_multiplier` — порог относительно фонового движения воды;
- `visual_vertical_shift` — минимальное вертикальное смещение в пикселях;
- `visual_template_confidence` — порог исчезновения шаблона;
- `visual_confirmation_frames` — число последовательных подтверждений.
- `visual_downward_velocity` — минимальная скорость резкого движения вниз;
- `visual_bite_window` — время связи погружения и исчезновения шаблона;
- `visual_tracker_lost_frames` — число кадров до повторного поиска;
- `visual_reacquire_radius` — допустимое расстояние повторного обнаружения;
- `loot_confirmation_*` — проверка исчезновения поплавка после клика.

Если auto detector не может построить цветовой профиль, бот автоматически
переходит к существующему template/motion fallback. Если спокойная вода вызывает ложные поклёвки, сначала увеличьте
`visual_motion_threshold` или `visual_confirmation_frames`. Если настоящая
поклёвка пропускается, немного уменьшите `visual_motion_threshold` и
`visual_vertical_shift`. Меняйте по одному параметру и повторяйте utility.

## Необязательно: определение поклёвки по звуку

Visual-режиму не нужны наушники, громкость или аудиоустройство. Старый WASAPI
детектор сохранён как запасной вариант. Чтобы включить его, измените:

```python
bite_detection_mode: str = "audio"
```

Сначала выведите список Windows WASAPI устройств:

```powershell
python tools/list_audio_devices.py
```

Ищите строку с вашими наушниками/колонками и `loopback=True`. Пример:

```text
index=12  loopback=True  rate=48000 channels=2  name=Speakers (...) [Loopback]
```

Если loopback-устройств несколько, в `config.py` укажите уникальную часть имени:

```python
audio_device_name: str | None = "Speakers"
```

Если оставить `None`, программа выберет первое найденное loopback-устройство.
Не указывайте вручную index: после перезагрузки Windows он может измениться.

### Калибровка audio-режима

Запустите WoW со своей обычной громкостью и выполните:

```powershell
python tools/test_audio_detection.py
```

Утилита сначала измеряет фоновый звук, затем показывает `rms`, `baseline`,
`threshold` и сообщения `SPIKE`/`BITE`. Во время теста вручную забросьте удочку.

Настраиваемые значения в `config.py`:

- `audio_calibration_chunks` — длительность начального измерения фона;
- `audio_threshold_multiplier` — во сколько раз всплеск должен быть громче фона;
- `minimum_audio_threshold` — минимальный абсолютный порог;
- `audio_consecutive_spikes` — сколько последовательных chunks подтверждают звук.

Если музыка вызывает ложную поклёвку, повысьте multiplier или число consecutive
spikes. Если настоящая поклёвка не определяется, немного уменьшите multiplier
или minimum threshold. После каждого изменения повторяйте тест.

## Шаг 10. Безопасный запуск без ввода

Откройте WoW, сделайте его активным и выполните (PNG в auto-режиме не нужны):

```powershell
python main.py --dry-run --debug --once
```

`--dry-run` не отправляет реальный keyboard/mouse input. Screenshot, OpenCV,
визуальный детектор и логирование продолжают работать. Поскольку заброс также
подавляется, нажмите игровую клавишу заброса сразу после сообщения
`DRY RUN: cast manually now`, чтобы auto detector увидел разницу кадров.
Проверка исчезновения после loot пропускается, потому что реальный клик не был
отправлен; в dry-run не следует ожидать сообщение `Loot confirmed`.

Проверьте логи и файлы `debug\latest_pre_cast.png`, `latest_post_cast.png`,
`latest_novelty_mask.png`, `latest_auto_candidates.png` и
`latest_colour_mask.png`. Не переходите к обычному запуску, пока detector не
находит правильный поплавок и не реагирует на поклёвку.

## Шаг 11. Обычный запуск

1. Запустите WoW и встаньте возле подходящей воды.
2. Проверьте клавиши Fishing и наживки.
3. Откройте PowerShell в проекте и активируйте окружение:

   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```

4. Запустите программу:

   ```powershell
   python main.py
   ```

5. Переключитесь в WoW. Программа не отправляет ввод, пока WoW не является
   активным foreground-окном.

Управление:

- **F8** — пауза или продолжение;
- **F10** — аварийная полная остановка;
- **Ctrl+C** в PowerShell — корректная остановка;
- `python main.py --once` — только одна попытка;
- `python main.py --debug` — подробные логи и перезапись последних debug PNG.
- `python main.py --full-window` — временно искать по всему окну, игнорируя
  сохранённую пользовательскую область.
- `python main.py --bite-mode auto`, `visual` или `audio` — временно выбрать
  способ определения поклёвки без редактирования `config.py`.

При F10 программа прекращает основной цикл, закрывает audio stream и пытается
отпустить Shift, Ctrl и Alt.

## Все основные параметры

Пользовательские параметры централизованы в `config.py`:

- `cast_key`, `bait_key` — игровые клавиши;
- `pause_key`, `stop_key` — глобальные hotkeys;
- `search_mode = "window"` — рекомендуемый поиск по всему клиентскому окну WoW;
- `search_region` — область для необязательного режима `"custom"`; визуально
  выбранная область хранится в `user_config.json` и имеет приоритет;
- `wow_window_titles` — разрешённые части названия окна;
- `bobber_confidence`, `grayscale_matching` — OpenCV;
- `bobber_search_timeout`, `fishing_attempt_timeout` — поиск и общий срок попытки;
- `bite_detection_mode` — основной `"auto"`, template fallback `"visual"` или
  запасной `"audio"`;
- `auto_*` — автоматическая цветовая и позиционная калибровка;
- `visual_*` — чувствительность визуального детектора;
- `cast_delay`, `post_loot_delay`, `retry_delay` — задержки;
- `use_bait`, `bait_interval_minutes`, `apply_bait_on_start` — наживка;
- `audio_device_name` и `audio_*` — звук;
- `debug` — постоянный диагностический режим.

Меняйте только значения справа от `=`. Сохраняйте кавычки у текста и не
удаляйте запятые/скобки. Перед редактированием полезно сделать копию файла.

## Типичные проблемы

### `py` или `python` не является командой

Переустановите Python 3.12 с флажком **Add python.exe to PATH**, закройте и снова
откройте PowerShell. Убедитесь, что окружение активировано.

### PowerShell запрещает `Activate.ps1`

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

Затем снова выполните `.\.venv\Scripts\Activate.ps1`.

### `ModuleNotFoundError`

Откройте PowerShell именно в папке проекта, активируйте `.venv` и выполните:

```powershell
python -m pip install -r requirements.txt
```

### `No readable PNG templates`

Для `auto` это нормально. Ошибка возникает только в ручном `visual` режиме:
добавьте `templates\bobber_01.png` либо вернитесь к `--bite-mode auto`.

### `Bobber not found`

Проверьте разрешение/масштаб, debug-изображение и тест OpenCV. Добавьте несколько
точных шаблонов. При ложных совпадениях выделите компактную область воды через
`--select-region`. Снижайте confidence небольшими шагами,
например `0.75` → `0.72`, иначе возможны клики по неправильным объектам.

### Мышь наводится не туда

Полностью перезапустите бот после смены Windows scaling и повторите
`python main.py --select-region`. Не запускайте отдельные компоненты с разными
DPI compatibility settings.

### Бот пишет `Waiting for WoW foreground window`

Сделайте WoW активным. Если название вашего клиента отличается, добавьте его
часть в `wow_window_titles` в `config.py`.

### Visual-режим не замечает поклёвку

Запустите `python tools/test_visual_bite_detection.py` и проверьте
`debug\latest_visual_bite.png`. Уменьшайте `visual_motion_threshold` и
`visual_vertical_shift` небольшими шагами. Убедитесь, что шаблон соответствует
текущему разрешению, UI scale и виду поплавка.

### Auto-режим пишет `colour_calibration_failed`

Шаблон не содержит достаточно насыщенного красного или синего пера. Обрежьте
PNG плотнее вокруг поплавка и не сохраняйте его в grayscale. До исправления бот
автоматически использует visual fallback.

### Auto-режим теряет подвижный поплавок

Проверьте `latest_colour_mask.png`. Увеличьте `auto_tracking_padding`, если перо
уходит за ROI, либо `auto_lost_frames`, если его ненадолго закрывает вода.
Не увеличивайте `auto_max_frame_shift` без необходимости: этот предел защищает
от переключения tracker на другой цветной объект.

### Visual-режим срабатывает на воду

Увеличьте `visual_motion_threshold`, `visual_motion_multiplier` или
`visual_confirmation_frames`. Не двигайте камеру во время заброса. Более тесный
и точный шаблон уменьшает влияние окружающей воды.

### `tracker_lost` или поплавок исчез сам

Это не считается поклёвкой без предварительного резкого движения вниз. Проверьте
шаблон и увеличьте `visual_bite_roi_padding` либо `visual_reacquire_radius`.
Сообщение `attempt_expired` означает нормальное окончание общего времени заброса.

### `Loot not confirmed`

Клик был отправлен, но шаблон не исчез за `loot_confirmation_timeout`. Бот не
кликает повторно из соображений безопасности. Проверьте наведение, foreground-
окно, кнопку Shift + Right Click и порог `loot_disappearance_confidence`.

### Нет WASAPI loopback в необязательном audio-режиме

Проект должен запускаться в Windows. Выберите и включите реальное output device,
запустите в нём звук, переустановите requirements и повторите
`python tools/list_audio_devices.py`. Проверяйте устройство с `loopback=True`.

### Ложные или пропущенные поклёвки в audio-режиме

Проверьте правильность output device, установите постоянную громкость WoW и
повторите audio calibration. Фоновая музыка и другие приложения на том же
устройстве также попадают в loopback.

### Hotkeys или ввод не работают

Убедитесь, что не запущен `--dry-run`. Проверьте F8/F10 на ноутбуке вместе с
клавишей Fn. WoW и Python должны иметь одинаковый уровень прав Windows.

## Обновление и повторный запуск

Обычно при следующем использовании достаточно трёх команд:

```powershell
cd C:\wow-fishing
.\.venv\Scripts\Activate.ps1
python main.py
```

После изменения UI scale нужны новые шаблоны. Режим всего окна автоматически
следует за размером и положением WoW; пользовательскую область после изменения
разрешения или расположения окна нужно выбрать заново. При смене устройства
вывода повторите калибровку только при использовании audio-режима.

## Архитектура проекта

- `main.py` — CLI и корректный запуск/остановка;
- `config.py` — все пользовательские параметры;
- `fishing_bot/bot.py` — state machine и основной цикл;
- `capture.py` / `bobber_detector.py` — MSS и OpenCV;
- `auto_bite_detector.py` — основной HSV/position detector с автокалибровкой;
- `visual_bite_detector.py` — template/motion fallback;
- `audio_detector.py` — необязательный WASAPI RMS fallback;
- `window_manager.py` / `input_controller.py` — защита foreground-ввода;
- `hotkeys.py` — глобальные F8/F10;
- `tools/` — отдельная диагностика экрана, OpenCV, visual bite и звука;
- `tests/` — тесты логики без WoW и Windows hardware.

Реальную интеграцию с названием окна WoW, WASAPI device, hotkeys, DPI,
наведением и Shift + Right Click необходимо проверить вручную на вашем Windows
компьютере с запущенной игрой.

Основной жизненный цикл: `CAST → SEARCH → TRACK → BITE → LOOT → VERIFY
DISAPPEARANCE`. После подтверждения либо безопасного timeout начинается новая
попытка с новым поиском поплавка.
